# The ONE source of the pip version cap.  Everything that upgrades pip and
# then installs requirements.txt reads this file:
#   CI: PIP_CONSTRAINT points at it, in each workflow that installs
#       requirements.txt (coverage-baseline, flake-checks, nix-check,
#       release, security-scan).
#   Dockerfile and deploy/cloud/Dockerfile.prod: COPY it, pip install -c.
#   deploy/linux/install.sh and deploy/distro/build-iso.sh: pip install -c
#       with the copy the installer just put in /opt/hart.
#   deploy/remote/install_remote.py: reads it here (_pip_cap).
# tests/unit/test_source_guard_one_pip_cap.py fails on a second copy.
#
# pip 26.3 (released 2026-11-02) refuses autobahn==23.1.2 from PyPI:
#   "Distributions from PyPI cannot declare direct URL dependencies.
#    autobahn depends on web3[ipfs] @ git+https://github.com/ethereum/web3.py.git
#    ... ; extra == "all""
# so `pip install -r requirements.txt` and pip-audit (whose own venv upgrades
# pip) failed before any test ran, and central's deploy of ca0852c0f failed
# at the requirements step (2026-11-10).  pip 26.2.2 installs it.  autobahn
# stays pinned at 23.1.2 for the reason given in requirements.txt; lift this
# cap when that pin moves to a release whose metadata pip accepts (24.4.2
# does).
pip<26.3
